This document maps canonical TiDB Cloud `plan` values to categories and stable `check_id` values.

## Applicability legend

| Mark | Meaning |
|---|---|
| **R** | Required attempt in default Health. Missing or unusable evidence returns N/A with a reason. |
| **C** | Capability-gated Health check. Run only after capability and source validation. |
| **D** | Explicit component deep dive only. |
| **X** | Excluded for this Plan. The runtime must not query it. |
| **—** | Product capability is not applicable to this Plan. |

`Unknown` is default-deny for every check except safe metadata needed to explain routing failure.

## Plan-specific default Health guidance

### Starter

Run CAT-00, CAT-01, CAT-02, CAT-03, CAT-04, and authorized product-state checks in CAT-09/CAT-11. Physical categories CAT-05 through CAT-08 and shared physical TiFlash evidence are excluded. Unsupported product evidence is N/A with a reason.

### Essential

Use the same logical-cluster boundary as Starter. Attempt keyspace-scoped provisioned capacity, available RU, read/write maximum RU, consumption and rc_wait corroboration when exposed. Never use parent-pool physical evidence.

### Premium

Use the same logical-cluster boundary. Attempt logical-cluster RU/RCU and KV request-wait queueing evidence when exposed. Shared-pool coprocessor wait, TiKV/PD CPU, nodes, storage and topology are excluded.

### Dedicated

Run tenant SQL and logical storage plus capability-gated full-stack CAT-05 through CAT-11. Every physical rule still requires route, ownership, label, permission, version, unit and source validation.

### BYOC

Use the Dedicated logical/full-stack category set, but treat cloud-provider and infrastructure evidence as capability-gated because metric ownership and provider integrations vary by deployment.

### Unknown

Default-deny. Only safe metadata required to explain routing failure may be emitted.

## Profile and scoring boundaries

- Default health evaluates R checks and C checks after capability validation.
- component_deep_dive evaluates only the explicitly requested component/category and does not silently expand scope.
- SQL Top-N checks are D checks and do not determine cluster Health by rank.
- N/A lowers confidence instead of severity.
- Snapshot evidence may supplement but never replace the required observation window.
- A check affects Health only when evidence, unit, denominator, scope, threshold or baseline, and persistence semantics are valid.
